# 独立审查单包迁移记录

> 此文记录 0.2.0 的历史迁移，不代表 DSH Custom Auto Review 0.3.0 已完成安装或 GUI 人工验收。当前行为与限制见根目录 README 和维护政策。

## 结果

本机已安装 `@local/dsh-independent-auto-review` 0.2.0，旧 settings companion 已移除。重启后的 Host 能读取原审查配置；用户确认新版表单「显示和保存都正常」。

审查与设置服务仍是两个平级 Host 组件。主包名称、`include:independent-auto-review` 和配置身份不变。最终读取保留了该安装的私有供应商和模型标识、`high` 思考强度以及 60000 毫秒超时；具体路由不随公开仓库分发。

## 最小改动范围

- 合并安装包、导出和 Client 入口，不保留旧包别名。
- 修复 GUI 请求先后顺序，移除多余的保存适配层和 Function.toString 构建。
- 只给三个 Config 标识字段增加同一 pattern，提前拒绝原本就不允许的空值及首尾空白。
- 原审查策略、fail-closed、后续 guard、取消排空、CAS 和未知字段保留不变。
- SDK 未修改；不声称解决其任意启动故障或自动回滚问题。

## 验证

120 项常规测试通过。独立冷迁移测试使用实际旧包和新产物，在三个顺序运行的测试 Host 进程中验证安装与旧配置恢复。这只是离线测试，不是新增的运行时容错逻辑。

实际安装最初没有停掉旧后台进程，导致缓存未刷新、设置组件未启动。用户批准结束旧进程后，通过 VS Code 扩展重新启动，随后 Host/Client 检查通过，用户确认显示和保存成功。没有把“重启扩展宿主”误当作后台进程已重启的证据。

## 用户最终边界

不再新增备份、防御性编程、重试、容错、备用路径或自动回滚。已有备份未删除或修改。没有新增恢复框架。

Profile 修改使用受支持的 Plugin Manager/CLI；没有手改 profile、修改主模型或 SDK、授予版本豁免、执行未批准脚本或自动选择 Auto。真实停机经过用户明确许可。

Teammate 必须与 Lead 同模型；未能确认一致后暂停委派，由 Lead 完成实现和验收。发布仅限原授权仓库，不强推或重写历史。

独立记录的限制：没有新的外部模型网关测试，没有单独记录 Reload 按钮及双主题/键盘验收。参见 [验证详情](gui-verification.md)。
